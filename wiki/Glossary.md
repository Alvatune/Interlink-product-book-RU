# Словарь

Словарь описывает целевую модель книги, согласованную 6 сентября 2026 года. Слова «версия», «сохранить», «зафиксировать» и «контекст» без уточнения ещё не определяют результат.

## Объект, инженерная версия и содержание

| Термин | Предметный смысл |
|---|---|
| Объект | Изделие, документ, организация, отправка или другой предмет, сохраняющий своё тождество при изменении данных |
| Инженерная версия | Отдельная линия развития конструкции или документа: например, версия Б корпуса насоса. Внутри неё могут появляться новые опубликованные состояния |
| Опубликованное состояние | Неизменяемое содержание определённой инженерной версии, сохранённое при явном завершении правки. Не новая инженерная версия автоматически |
| Рабочее содержание, черновик | Ещё не опубликованная правка выбранной версии в рабочей области. Сохранение черновика не меняет официальное содержание |
| Точное содержание | Конкретное неизменяемое состояние или сохранённое свидетельство, которое читается без повторного выбора «последнего» |
| Изменяемая запись | Данные, которые можно поправить с проверкой, что их не изменил другой участник. Например, карточка поставщика с контактными реквизитами. Исправление номера телефона меняет реквизит этой карточки, а не создаёт отдельную инженерную версию |
| Неизменяемый факт | Запись события или наблюдения. Исправление оформляется новым связанным фактом, а не стиранием прежнего |
| Позиция состава | Определённое место использования компонента со своими количеством, обозначением и условиями |
| Нить позиции | Устойчивая идентичность места между состояниями состава. Локальную позицию определяют владелец, вид связи и нить. Конкретное использование в развёрнутом составе дополнительно определяется корнем и полным путём |

Конструктор исправил шероховатость в версии Б корпуса. Промежуточное сохранение меняет только рабочее содержание. После явной публикации появляется новое состояние той же версии Б. Переход к версии В — отдельное инженерное решение. Ранее выданный чертёж продолжает ссылаться на прежнее точное содержание.

В логистическом примере контактный номер исправляется в изменяемой карточке перевозчика. Факт приёмки груза хранится отдельной записью о событии. Если в ней обнаружена ошибка, создаётся корректирующая запись со ссылкой на исходную; история события сохраняется. Подробнее — [[Общее объектное основание|Object-foundation]].

## Работа, чтение и согласование

| Термин | Предметный смысл |
|---|---|
| Рабочая область | Место подготовки незавершённой работы; может жить дольше одной публикации и содержать несколько проработок |
| Контекст подбора | Сохраняемый выбор версий и способа чтения их содержания для совместной работы. Не равен рабочей области, извещению или пакету |
| Условия чтения и подбора | Полный набор входов конкретного просмотра: корень, контекст, серия, дата, правила, доступ и требуемая точность |
| Пакет изменения | Выбранный согласованный набор будущих действий, который готовят, проверяют и проводят как одно предметное изменение |
| Комплект пакетов | Несколько пакетов для общего проведения «всё или ничего». Объединение контекстов само по себе этого не требует |
| Проведение изменения | Фиксация ровно проверенных действий. Для инженерных правок публикует состояния; для обычных записей выполняет разрешённое изменение |
| Итерация | Долговечное именованное сохранение выбранного содержания объектов или рабочих правок |
| Восстановление итерации | Возврат выбранного содержания в проверенные рабочие адресаты. Само по себе не публикует новые состояния |
| Предмет согласования | Точное содержание и существенные основания, которые одобрил человек. Одобрение не переносится автоматически на другие данные |

Два контекста могут выбирать одну инженерную версию и всё же конфликтовать: один требует её прежнее точное состояние, другой — рабочую правку. И наоборот, два отдела могут совместно видеть будущий состав, не обязывая друг друга завершать работу одновременно. См. [[Контексты подбора|Selection-contexts]] и [[Рабочие области|Workspaces-and-parallel-work]].

## Конкретизация и подбор

| Термин | Предметный смысл |
|---|---|
| Жёсткая конкретизация | Требование остаться на указанной инженерной версии. Само по себе не фиксирует её содержание навсегда |
| Точная фиксация содержания | Требование читать определённое опубликованное состояние, а не более новое содержание той же версии |
| Мягкая конкретизация | Сохраняемое намерение использовать указанную версию в позиции; его учёт зависит от режима и правил. Не временная настройка пакета |
| Временное предпочтение | Отдельный ограниченный выбор для проработки, не подмена долговечной мягкой конкретизации |
| Назначенная основная версия | Версия, явно выбранная основной. Не обязана быть самой новой |
| Последняя допустимая версия | Самая новая по принятому порядку среди разрешённых в данном сценарии |
| Применяемость | Условия действия: головное изделие, серия, заводской номер, дата и другие объявленные предметные признаки |
| Степень инженерной готовности | Уровень готовности версии. Не заменяет полный жизненный цикл, подписи, права и задания |
| Правило подбора | Управляемое правило выбора версии и содержания при заданных входах |
| Резервный выбор | Заранее разрешённый запасной способ с явной причиной. Не средство обойти жёсткую привязку, запрет доступа или несовместимость |
| Основание выбора | Объяснение, какие данные и правила привели к результату |
| Подходящая версия не найдена | Позиция нужна, но допустимого результата нет. Позиция не исчезает молча |
| Условие включения позиции | Правило, определяющее, нужна ли позиция в выбранной комплектации |

Если насос жёстко закреплён за версией 02, версия 03 не подставляется вместо неё. Но для воспроизводимого испытания нужно указать также точное состояние версии 02. Мягкое намерение «использовать 02» — третья ситуация: оно остаётся данными позиции, даже когда разрешённый режим временно его не учитывает. См. [[Мягкая конкретизация|Selection-soft-concretion]].

## Таблицы, замены и совместимость

| Термин | Предметный смысл |
|---|---|
| Индексируемый набор данных | Справочные строки или значения для быстрого поиска по объявленным признакам, не только вложенный файл |
| Полная многомерная таблица | Сетка всех сочетаний выбранных конечных осей. Наличие клетки не гарантирует, что значение известно и пригодно для любой цели |
| Координатная карта | Разреженное сопоставление сочетаний признаков со значениями, объектами, версиями или наборами кандидатов |
| Координаты | Именованные значения осей: например, температура 80 °C и материал корпуса сталь. Не обязательно геометрические координаты |
| Точная редакция таблицы | Зафиксированное справочное основание. Живая ссылка из клетки требует отдельного выбора точного содержания цели |
| Допустимая замена | Направленное разрешение заменить определённый объект или комплект в заданных условиях |
| Библиотека альтернатив | Переиспользуемые описания вариантов. Их наличие не означает выбор для каждого заказа |
| Контекстный выбор альтернативы | Решение использовать вариант в определённом заказе, составе или месте применения |
| Совместимость | Соответствие полного комплекта всем обязательным ограничениям, проверенным совместно |
| Факт применения | Изменение конкретных данных по выбранному разрешённому плану |
| Факт установки | Подтверждённое физическое действие: что действительно сняли и поставили |

Пустая клетка сама по себе не означает запрет. Совместимость каждой детали с контроллером по отдельности не доказывает, что весь шкаф укладывается в его ресурс. Эти различия раскрыты в [[Табличных данных|Tabular-data]] и [[Матрицах совместимости|Compatibility-matrices]].

## Заказ, история и агенты

| Термин | Предметный смысл |
|---|---|
| Живой заказ | Изменяемое описание потребности и её подготовки |
| Снимок передачи | Неизменяемый полный состав конкретной выдачи, который не пересчитывается задним числом |
| Физический экземпляр | Конкретная изготовленная единица с собственной идентичностью |
| Партия | Прослеживаемая группа единиц; не один большой экземпляр |
| Функциональное место | Место выполнения функции, сохраняющееся при замене оборудования |
| Фактический состав | Что действительно установлено в экземпляре, с учётом подтверждённых событий |
| Точные основания решения | Содержание объектов, файлов, правил и наблюдений, использованное при принятии решения |
| Фактически выданный контекст | Что действительно показали человеку или агенту: данные, страницы, выдержки и ограничения полноты |
| Квитанция операции | Устойчивое подтверждение результата конкретного намерения, помогающее избежать повторного эффекта |
| Неизвестный исход | Ответ потерян или подтверждения недостаточно. Это не доказательство ни успеха, ни отката |
| Удержание истории | Сохранение данных, файлов и способов их чтения на срок и для цели, заданных политикой |
| Делегирование полномочий | Явно ограниченное право действовать от имени человека или другого исполнителя; не бессрочная копия всех его прав |

Разрешение поставить новый двигатель не переписывает фактический состав станка: нужен факт монтажа. Журнал «агент прочитал чертёж» тоже недостаточен: важно сохранить, какой чертёж и какую его часть агент действительно получил.
